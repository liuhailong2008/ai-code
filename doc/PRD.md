## 2. 页面规划

### 2.1 监控中心 页面
展示核心监控数据。
图形方式显示数据中心网络：
- 三地六中心。
- 每个中心分核心层、汇聚层、接入层。
- 图形方式显示连通性。

#### 2.1.1 连通性监控 页面 
展示子页面核心监控。

##### 2.1.1.1 机房连通性监控 页面 
用热力图显示机房连通性，横坐标和纵坐标分别为各机房：IDC1-IDC7。
交叉处格子显示连通性，连通性为耗时，耗时100ms以下为连通，100-250ms为故障隐患，250ms以上为断开，用不同颜色展示。 
耗时可切换：平均耗时、999分位耗时、最大耗时。

【评审建议】热力图格子颜色需定义色阶：绿色(0-100ms) → 黄色(100-250ms) → 红色(250ms+)，建议增加透明度映射丢包率。

##### 2.1.1.2 Leaf连通性监控 页面 
用热力图显示某个机房的Leaf连通性，首先选择IDC1-IDC7机房中的一个。
横坐标和纵坐标分别为各机房：Leaf1-Leaf25。
交叉处格子显示连通性，连通性为耗时，耗时100ms以下为连通，100-250ms为故障隐患，250ms以上为断开，用不同颜色展示。 
耗时可切换：平均耗时、999分位耗时、最大耗时。

【评审建议】Leaf数量可能不止25个，建议改为动态获取；热力图需支持滚动或缩放。

#### 2.1.2 耗时监控 页面
用散点图显示某个机房的监控耗时，首先选择IDC1-IDC7机房中的一个；并指定时间区间，每分钟1个区间，可以通过时间轴选择历史上某一分钟，也可以通过动画形式显示连续多个分钟的数据。
横坐标为耗时，纵坐标为丢包率。
耗时和丢包率的统计方式，可以选择：平均、999分位、最大。
用一个点显示一个Leaf的情况，汇总这台Leaf作为源或作为目标的所有原始监控数据，并汇总。

【评审建议】
- 散点图建议增加hover提示显示详细信息
- 时间轴需支持拖拽选择范围
- 动画播放需有播放/暂停/速度控制
- 数据点过多时建议采样或聚合

#### 2.1.3 告警管理 页面

##### 2.1.3.1 未恢复告警 页面
显示未恢复的告警，包括两类告警： 原始数据异常、故障告警。
其中，原始数据异常，为根据规则触发的原始告警，原始数据异常经过自动研判后才可能判定为 故障告警。
故障告警中，显示未恢复的告警列表。
每个告警包括：触发时间、连通性监控图片，智能研判结果，相关网络设备，处置建议。

【评审建议】
- 告警列表需支持排序和过滤
- 图片加载考虑懒加载
- 处置建议需提供快捷操作按钮

##### 2.1.3.2 历史告警 页面
显示历史告警。

##### 2.1.3.3 告警配置 页面
配置原始告警规则。
每条规则包括：规则名称，告警rule，为prometheus告警规则。

### 2.2 任务中心
#### 2.2.1 设备管理 页面
包括： 全部设备、探测代理、探测目标、主机覆盖度分析。

##### 2.2.1.1 设备管理 页面
全部设备显示自cmdb同步的全部主机设备的清单，包括：设备序列号、机房、环境、网络区域、设备IP、Leaf、机柜、应用、运维团队。
可以在这个页面选择某主机选中为"探测代理"或"探测目标"。

【评审建议】
- 需支持CMDB同步时间显示
- 批量操作需二次确认
- 分页建议后端分页

##### 2.2.1.2 探测代理 页面
显示探测代理。

##### 2.2.1.3 探测目标 页面
显示探测目标。

#### 2.2.2 策略管理 ���面
管理探测策略。
每个探测策略包括：源机房、目标机房、源数量（每个机柜下选择的探测代理的数量）、目标数量（每个机房下选择的Leaf数量）。
针对每个策略，可以：生成探测任务、重新生成探测任务、下发探测任务。
探测任务状态包括：新生成、待下发、已下发、待清理。

【评审建议】
- 策略数量可能很多，需支持搜索和过滤
- 下发操作需显示进度
- 状态变更需有日志

#### 2.2.3 任务管理 页面
显示生成的全部探测任务。

## 3. 通用需求

### 3.1 响应式设计
- 桌面端优先，平板适配
- 监控大屏需支持1920x1080及以上分辨率

### 3.2 性能要求
- 页面加载时间 < 3秒
- 图表渲染帧率 ≥ 30fps
- 大量数据需支持虚拟滚动

### 3.3 无障碍
- 键盘导航支持
- 颜色对比度 ≥ 4.5:1
- ARIA标签

---

## 4. 网络监控专家评审补充

### 4.1 数据展示规范

| 指标 | 阈值定义 | 展示建议 |
|------|----------|----------|
| 连通耗时 < 100ms | 正常 | 绿色 |
| 连通耗时 100-250ms | 警告 | 黄色/橙色 |
| 连通耗时 > 250ms | 严重 | 红色 |
| 丢包率 0-0.1% | 正常 | 绿色 |
| 丢包率 0.1-1% | 警告 | 黄色 |
| 丢包率 > 1% | 严重 | 红色 |

### 4.2 实时性要求
- 监控数据刷新频率：建议5秒/次
- 告警延迟：< 10秒触发
- 拓扑图节点建议 ≤ 100个/视图（性能考虑）

### 4.3 数据量估算
- 7个IDC × 25个Leaf = 175个节点
- 全量连接矩阵：175 × 175 = 30,625个数据点
- 建议热力图采用聚合或降采样

## 5. 系统开发专家评审补充

### 5.1 技术选型建议
| 场景 | 推荐方案 |
|------|----------|
| 热力图 | ECharts heatmap 或 D3.js |
| 散点图 | ECharts scatter |
| 拓扑图 | D3.js force-directed 或 vis-network |
| 表格 | 自建（符合现有 Demo 风格） |
| 状态管理 | Composition API Store |
| 时间选择 | 自建时间选择器 |

### 5.2 数据源方案
**采用 Mock 数据方案**（前后端解耦开发）

- 前端使用本地 Mock 数据文件
- 数据结构模拟真实 API 响应
- 可无缝切换真实 API（仅需替换数据获取层）

### 5.3 Mock 数据文件规划
```
src/modules/monitoring/mocks/
├── connectivity.json    # 机房连通性数据
├── leaf-connectivity.json  # Leaf连通性数据
├── latency.json       # 耗时监控数据
└── alerts.json      # 告警数据

src/modules/tasks/mocks/
├── devices.json     # 设备列表
├── strategies.json # 策略列表
└── tasks.json     # 任务列表

src/modules/config/mocks/
└── agents.json     # 代理列表
```

### 5.2 API 设计建议
```javascript
// 建议的 API 接口
GET /api/monitor/connectivity?idc={idc}&metric={avg|p99|max}
GET /api/monitor/leaf-connectivity?idc={idc}&leaf={leaf}
GET /api/monitor/latency?idc={idc}&time_range={start:end}
GET /api/alerts?status={active|history}&page={n}&size={n}
POST /api/alerts/rules
GET /api/devices?type={all|agent|target}&sync_time={timestamp}
GET /api/strategies
POST /api/strategies/{id}/generate-task
POST /api/strategies/{id}/dispatch
GET /api/agents?status={online|offline}
POST /api/agents/{id}/upgrade
POST /api/agents/{id}/start
POST /api/agents/{id}/stop
```

### 5.3 关键交互
- 热力图格子点击 → 跳转详情或展开详情面板
- 散点图点hover → 显示Leaf详细信息tooltip
- 告警行点击 → 展开详情抽屉
- 设备行双击 → 打开编辑弹窗

### 5.4 安全考虑
- 敏感操作需二次确认（停止agent、删除策略）
- API需认证和权限控制
- 图表数据需防XSS

## 6. 运维专家视角补充（完整页面开发规范）

### 6.1 机房连通性热力图详细规范

#### 6.1.1 数据源
- 数据来源：ping探测结果
- 数据粒度：IDC级别（7个机房 × 7个机房 = 49个数据点）

#### 6.1.2 展示规范
| 字段 | 说明 |
|------|------|
| 维度 | 源IDC → 目标IDC |
| 值 | 耗时（ms）/丢包率（%） |
| 颜色映射 | 耗时：绿→黄→红；丢包率：透明度 |
| 空值处理 | 灰色显示"无数据" |

#### 6.1.3 交互
- 点击格子 → 跳转该链路详情页
- hover → tooltip显示：源IDC、目标IDC、耗时、丢包率、样本数

#### 6.1.4 筛选条件
- 耗时类型：平均 / P99 / 最大
- 时间范围：近5分钟 / 近1小时 / 自定义

---

### 6.2 Leaf连通性热力图详细规范

#### 6.2.1 数据源
- 数据来源：ping探测结果
- 数据粒度：Leaf级别（25个Leaf × 25个Leaf = 625个数据点/机房）

#### 6.2.2 展示规范
| 字段 | 说明 |
|------|------|
| 维度 | 源Leaf → 目标Leaf |
| 值 | 耗时（ms）/丢包率（%） |

#### 6.2.3 交互
- IDC选择下拉框 → 切换机房
- 耗时类型切换 → 重新计算颜色
- 点击格子 → 显示该对Leaf的详细历史

---

### 6.3 耗时监控散点图详细规范

#### 6.3.1 数据源
- 数据来源：每个Leaf的探测数据汇总
- 数据粒度：每个点 = 1个Leaf的汇总数据

#### 6.3.2 坐标定义
- X轴：耗时（ms）
- Y轴：丢包率（%）
- 点大小：样本数
- 点颜色：耗时状态（正常/警告/严重）

#### 6.3.3 交互
- IDC选择 → 切换机房
- 时间选择器 → 支持绝对时间/相对时间
- 动画播放 → 可选速度（1x/2x/5x）
- hover点 → 显示：Leaf名称、IP、耗时、丢包率、样本数
